AI Agent Governance

What controls an AI agent actually needs, what Amazon Bedrock, Google Cloud, Microsoft Copilot and Microsoft Foundry each give you, and ten exercises that end in deployed infrastructure.

Every claim in the reference was checked against the vendor's own documentation on one date, with a source link and an explicit list of what could not be verified. Three of the four platforms renamed something during 2026.

Ten control families

Platform-neutral on purpose, so you can compare Bedrock with Foundry rather than comparing two marketing vocabularies. The order follows a request through an agent.

  1. 1

    Identity

    Who is this agent, as distinct from the person who triggered it?

  2. 2

    Authorization

    What may it do, and is that the least it needs?

  3. 3

    Input controls

    What reaches its context, and who can influence that?

  4. 4

    Output controls

    What may leave, and what must never leave?

  5. 5

    Action controls

    Which actions change the world, and who approves those?

  6. 6

    Data boundary

    Where does the data sit, who holds the keys, how long is it kept?

  7. 7

    Observability

    Could you reconstruct a single decision six months from now?

  8. 8

    Evaluation

    How do you know it still behaves, after the last change?

  9. 9

    Cost and quota

    What stops one loop from spending the quarter's budget overnight?

  10. 10

    Lifecycle

    Who approved this version, and how would you withdraw it?

Three things nobody does well

A matrix of ticks implies more maturity than exists, so this belongs next to it.

  • Agent identity has no standard. All four have shipped something; none of it interoperates. The standards work is real and early.
  • Input filtering is a rate reducer on all four. The model cannot reliably separate instructions from content. What differs is whether you get somewhere to put a control at the point of action, and only two currently do.
  • Evidence is harder than control. Configuring a guardrail takes an afternoon. Reconstructing one agent decision from six months ago takes a system nobody budgeted for.

Per platform

Amazon Bedrock and AgentCore

Strongest data defaults and tool authorization. Opens with six things most existing material gets wrong, starting with the fact that guardrails do not work on one of the two inference endpoints.

Gemini Enterprise Agent Platform

Strongest identity design, and the source of the best single idea here: floor settings. Renamed from Vertex AI, though the machine-readable identifiers did not change.

Microsoft Copilot and Copilot Studio

Strongest lifecycle governance, for agents built by people who are not engineers. A new control plane arrived in 2026 and the old agent registry was retired.

Microsoft Foundry

Strongest evaluation and the only platform that can place a control on a tool call. Also the one where a guardrail fails open silently if you reference it wrongly.

Frameworks and regulations

Where these controls land against the EU AI Act as amended in July 2026, the NIST risk management framework, ISO 42001 and both OWASP lists. The high-risk deadlines moved, so anything written before August 2026 has the wrong dates.

Ten exercises

Small programs you finish yourself, with checks that tell you when they work. In this order on purpose: the first produces requirements, the next four produce controls and evidence, the middle four deploy real infrastructure, and the last refuses to ship when any of the others is unhappy.

  1. Control inventory

    Derive the controls an agent's design forces on you, as code rather than as a document.

  2. Policy as code

    A decision engine between the model and your tools. Default deny, deny wins, every decision recorded.

  3. Injection testing

    Build a bad filter, measure it honestly, and watch five of six evasions walk past.

  4. Audit trail

    A hash-chained record that answers why it did that, and breaks visibly when edited.

  5. Evaluation gate

    A version that scores higher overall and is still blocked, because one safety case regressed.

  6. Deploy a Bedrock guardrailTerraform

    Guardrail, published version, invocation logging, and the policy that makes using it compulsory.

  7. Deploy Model ArmorTerraform

    A template, a floor setting nobody can go below, a model allowlist, and an agent with its own identity.

  8. Deploy a Foundry guardrailBicep

    Both Prompt Shields, key auth disabled, private access, and two decisions you cannot change later.

  9. Govern Microsoft Copilot

    A conformance check across four admin centres, including the sensitivity label trap.

  10. The release pipeline

    One gate over every signal, with waivers that have an owner and an expiry date.

The deployment ones work without a cloud account

Exercises 6 to 9 are graded by reading the infrastructure code you write, so they pass on a laptop with no credentials and no cost. Applying them for real is optional, and each README carries the commands, the cost note and the teardown.

Running it

Node 20 or newer. No API keys. Nothing in this repository calls a model.

git clone https://github.com/BaluRaut/ai-agent-governance.git
cd ai-agent-governance
npm install

Honest limits

Verified on one date
22 September 2026. Six of the platform pages record facts that changed during 2026, including a rename on each of the three clouds and a formally amended EU AI Act timeline. Each reference page ends with a list of what could not be verified, so you can tell a gap from a fact.
Nothing here was applied to a live account
The infrastructure code is written against the documented resource schemas and checked for conformance. It has not been deployed. Provider schemas move, so run terraform validate against the current provider before you apply anything.
This is not legal advice
The framework mapping is an engineer's reading of primary sources. Where a conclusion is an inference rather than something a regulator has stated, it is marked as one.
Why the exercises have no model calls
So they run anywhere, cost nothing, and give the same answer twice. The trade is that the injection filter you build in exercise 3 is cruder than a commercial one. That is the point of the exercise: the commercial one has better numbers and the same shape of gap.
